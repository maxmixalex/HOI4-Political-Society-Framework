# Political society interface

PSF replaces the political party wheel and native ideology/party labels in the domestic politics and diplomacy views with **two live pies**, large governing-party and ideology icons, a compact national summary and an optional sidebar. Clicking the governing-party icon or either pie opens **Organizations**; clicking the ideology icon opens **Spectrum**. The sidebar occupies map space immediately to the right of the existing 550-pixel native window.

## Views

| View | Display and interaction |
| --- | --- |
| National summary | Support and influence pies, actual regime and the governing party's name, with a caretaker fallback. Large party and ideology images are live, clickable controls. The domestic summary additionally shows government support, effective influence, legitimacy and organization count. Native tooltips name the full government/alliance and distinguish institutions from the government's political program. |
| Organizations | Full profile roster, including explicitly labelled inactive organizations. Compact 44-pixel rows use the original game's `GFX_tiled_window_small_small` frame and show short name, native or custom icon, an explicit chart-color swatch, modified support, effective influence, modified satisfaction and activity status. Legal governing members receive a green Government label. Numeric values and status occupy separate cells. Select any row for details. |
| Organization details | Full name, large icon in a clipped art frame, organization kind, legal status, independent governing role, ideology and its small icon, current active alliance memberships, a scrolling description, live values and every configured issue position. Multiple memberships are preserved; an independent government need not belong to an alliance. Tooltips show the full membership list, base values, modifier-adjusted influence and named modifier sources with remaining days. Domestic-only actions activate, ban or legalize the group. |
| Spectrum | Issue charts compare actual institutions, the governing program and every active organization in separate horizontal lanes. Icons read live position variables. A regime's unspecified axis is hidden rather than plotted at a fictional zero; a caretaker has no government-program lane. Organizations with identical positions stay separately accessible. Only the horizontal coordinate carries political meaning. Hovering explains the axis and endpoints; clicking an organization opens its details. |
| Alliances | Compact framed entries show each authored alliance, live government/opposition/electoral role, cohesion, member count, effective influence and members. Tooltips include satisfaction and the complete member list. No transitional cabinet or mandatory governing alliance is invented. Dissolved alliances retain their explicit status; organization affiliation summaries omit them. |

The sidebar uses the native header strip, title font, close button and selected-tab appearance. Long lists and charts use the game's existing `right_vertical_slider`, mouse wheel input and smooth scrolling. Every scroll page has `clipping = yes`, a transparent native background, a 14-pixel scrollbar gutter and a wheel step. The background is required for scrolling: both KR's intro screen and TNO's doctrine view document this native behavior. Merely declaring a scrollbar without that background was insufficient. Long organization descriptions use the native textbox scrollbar inside the page.

The sidebar is 414×590 logical pixels, with a 396×486 page viewport beginning below the header and tabs. The combined native view plus sidebar needs approximately 966 logical pixels of horizontal room. The sidebar bottom is at logical screen Y=668 with the supplied 78-pixel native top offset. A usable logical canvas therefore needs at least 966×668 pixels; 1280×720 at 100% and 1920×1080 at 150% meet these geometric limits. These are bounds calculations, not completed engine scaling tests. A 1366×768 window at 125% does not meet the height limit, so it requires a lower game UI scale. The native scrollbar exposes content longer than the viewport; it does not make a physically off-screen viewport usable.

## Two independent pies

Both domestic politics and foreign diplomacy display two 63-pixel pies with the game's original `GFX_pol_piechart_overlay_63x63` mask. The support pie normalizes active organizations marked `electoral`; overlapping approval of trade unions and other civil organizations does not become additional election votes. The influence pie includes every active organization's effective influence, after modifiers and legal-status suppression. Political support can therefore remain substantial after a ban while the same group's usable institutional influence falls.

`psf/charts.py` partitions the inner disk into 180 pre-oriented sectors. The 63-pixel canvas now reserves a 4-pixel inset for the native bezel; colored pixels lie within radius 27, preventing the overflow visible in the supplied diplomacy screenshot. Every inner-disk pixel belongs to exactly one sector, which avoids the gaps created by rotating narrow antialiased wedge textures. Angular slots smaller than one pixel remain transparent without changing the 180-slot runtime contract. The inset is based on the screenshot and native sprite dimensions: the source archive did not include DDS payloads, so it is not an alpha-mask measurement.

Cropping each sector's frame strip limits texture storage. Frames use the organization's authored `color` (`#RRGGBB` or integer RGB channels) or the stable ID-derived fallback when no color is specified. The same color appears in list/detail swatches and pie-tooltip keys, including when an author supplies custom icon graphics. Native icon artwork remains independent of chart color. A zero total produces a neutral disk and a meaningful no-data tooltip.

`psf_update_charts_<profile>` runs after the runtime has recalculated modifiers and legal status. It caches `psf_pie_support_frames` and `psf_pie_influence_frames`, plus each organization's normalized `*_support_share` and `*_influence_share`. Cumulative boundaries are rounded once using the documented `round_temp_variable`, so independently rounded shares cannot leave gaps or overfill the circle. The 180-sector image is quantized to roughly 0.56 percentage points; native tooltips retain the normalized numeric values. The domestic summary uses `ROOT.psf_ui_revision` to avoid unnecessary property updates. Foreign summaries and icons deliberately have no `dirty` restriction: two countries can have the same revision number, and selecting the second country must refresh its data immediately without waiting for a daily update or modifying foreign state. The engine's documented default scripted-GUI refresh handles country-selection interaction.

## Country selection

Both native selection routes already expose a selected-country **party** field. `psf/frontend.py` uses that real engine binding: date-specific country history temporarily supplies a PSF presentation name containing the governing party, regime, identity graphics and two normalized pies. The field has a reserved political region in both the map-selection and interesting-country panels. It does not invent a campaign-only scripted-GUI country context in the lobby. Campaign startup/bootstrap restores ordinary native party names.

The important-country panel reserves a 305×225 political region at (35,477), with a 305×170 native party field below its labels. The portrait and frame move 60 pixels right to keep the expanded political region separate; the country's title keeps its original right edge. The map-selection party region remains 350×170. Party and ideology large icons and both pies therefore fit in the dedicated presentation rather than occupying the historical text. These are emitted geometry contracts; the installed game's texticon baselines still need an engine rendering check.

This layout is enabled only with the strict adapter's automatic country-history binding. Compat mode preserves the complete native frontend layout, so its original fields remain visible when no PSF presentation has been prepared.

The original historical description remains separate. No table, PSF notice or chart is prepended to that prose. Its engine-owned textbox keeps the original identity and ancestry, with a 160-pixel viewport and `standardtext_slider`. Political snapshots apply the profile's dated `start_overrides`; they are opening data rather than campaign simulation before the start button is pressed. See [BOOKMARKS.md](BOOKMARKS.md) for exact date handling, frontend layout and the remaining need to verify the native renderer's texticon baselines in-game.

## Native window safety

`psf/ui.py::patch_native` makes conservative edits to the supplied native GUI definitions. Obsolete widgets get native `hide = yes` and move horizontally off-screen as a fallback if engine code subsequently calls `show`. Their original Y positions are retained so the diplomacy scrollbar does not gain a giant negative vertical extent:

- `countrypoliticsview.gui`: move `chart_explanation`, `political_pie_chart`, the old ideology strip, and the ideology/election text off-screen. Keep the `ruling_party_info` container itself because it also contains faction and balance-of-power controls.
- `countrydiplomacyview.gui`: move the ideology icon and obsolete party/pie containers off-screen. Preserve the leader, national focus, diplomatic actions, intelligence and relation widgets.
- `frontendgamesetupview.gui`: move the obsolete political wheel and ideology/government/election fields off-screen; retain and reposition both native party fields to carry the selected-country political presentation. Preserve leader/spirit entries and every named widget's ancestry.

All generated `.gui` and `.gfx` files use **UTF-8 without BOM**. The engine log supplied for this repair showed the BOM becoming part of `guiTypes`/`spriteTypes`, preventing those root declarations from loading and culminating in `Undefined GUI_TYPE: frontendgamesetupview`. Localization `.yml` retains its required UTF-8 BOM. The two readers' encoding requirements must not be conflated.

The domestic roots attach through `parent_window_token = politics_tab`; diplomatic roots use `selected_country_view_diplomacy`. The latter is demonstrated by the supplied KR `00_economic_spheres.txt` and PB `PB_faction_icons.txt`, and is explicitly documented in the vendored CWT token list as restricted to the diplomacy tab. Switching to the intelligence tab therefore hides the PSF diplomatic views with the native diplomacy content. The implementation no longer assumes that an arbitrary nested native container has a generated `_instance` name. Those failed mounts were the cause of the summaries and sidebar appearing over the resource bar in the supplied screenshots.

The two native tokens have different origins. The diplomatic token is inside `country_info`, which begins 50 pixels below the native window root. Its summary therefore starts at token Y=110, or root Y=160; the sidebar uses token Y=-50 to align its header with the native window top. Applying the political coordinate origin to both contexts placed the foreign summary over the national-focus area in the later supplied screenshots.

The domestic summary reserves four image cells for party, ideology, support and influence, followed by 212 pixels of text. The images themselves open the sidebar, replacing the two text buttons that previously used that space. Diplomacy places the governing party in a 72×68 window within the original ideology-icon area above the tab strip; its summary contains the ideology image and two pies, with 152-pixel regime/party labels allowed two lines each. These text regions have full tooltips. Native national-focus artwork and leader portraits retain their original positions. Each dynamic image is a direct child of its own scripted window and reads an explicitly scoped getter.

The sidebar header owns the tab and close buttons. Every profile's group list, spectrum and alliances page, plus each organization's details page, is a separate top-level GUI definition with its own scripted-GUI `visible` condition. A page attaches to the appropriate header through `parent_scripted_gui`. Its condition includes initialization, the viewing player's open/page/selection state, and the viewed country's profile. The pages cannot be simultaneously enabled by the generated conditions. A stale detail selection after changing countries selects the new country's group list. Pages and headers have no data-only `dirty` restriction: player navigation must remain responsive while the game is paused or the foreign country's data revision is unchanged.

Every live frame, live position, click action and visibility callback refers to a **direct child of its owning window**. In particular, the 360 pie sectors belong directly to each summary, and each spectrum marker belongs directly to its profile's spectrum page. The generator no longer relies on callbacks traversing multiple nested profile, page and row containers. Runtime refresh stores the clamped axis position plus 184 in `psf_g_<id>_ui_position_<axis>`; marker centers then move from X=92 to X=292 on their 200-pixel tracks. All groups retain separate 18-pixel lanes.

The summaries have opaque, correctly sized backgrounds to cover the obsolete artwork beneath their replacement areas. Top-level windows are split into files at complete window boundaries under the validator's discovery limit. No controls are truncated to achieve a file-size target.

The patcher tokenizes the real tree, ignores comments and quoted braces, and requires every targeted widget to exist exactly once in its expected parent. It fails on an unexpected game layout rather than silently deleting or replacing a different widget. It verifies that all 1,095 original named widgets retain their type, name and named ancestry. The source snapshot SHA-256 values and exact hidden paths are written to `psf_ui_manifest.json` in the compiled content pack.

PSF does **not** globally replace `GFX_political_chart`: that sprite is also used for unrelated faction-influence charts. Trade-resource pies and other nonparty charts retain their normal behavior.

These complete native GUI files are version-specific overrides. A total conversion or game update that changes them needs a deliberate UI compatibility patch. A content author can pass another native interface directory to `generate_ui(..., vanilla_path=...)`; the same structural checks apply. Shipped source snapshots reside under `psf/assets/native_gui` and are included in the installed Python package. Their underlying source remains Paradox material; the repository's code license does not relicense those game-derived definitions.

## Scope and multiplayer behavior

A domestic view uses `player_context`. Diplomacy uses `selected_country_context`: the target is `THIS`, while `ROOT` is the viewing player. Domestic dynamic text, scripted-localization calls, chart frames and marker positions explicitly read `ROOT`; the diplomatic equivalents explicitly read `THIS`. GUI localization keys are separated by context so a player-context textbox cannot lose its country scope and display `[PSFUIRegime]` or a raw variable expression. KR's native politics widgets also explicitly qualify their dynamic getter with `ROOT`. Every UI state assignment is explicitly `ROOT.psf_ui_*`.

Opening one of the player's own summary controls first calls `psf_bootstrap`, then changes the UI selection. Bootstrap initializes missing PSF data or recomputes existing derived values; it does not advance a day, reset base attributes or expire modifier sources. Foreign summary controls only change the viewing player's UI state. New-game country-history initialization is handled by the runtime/compiler, so the summary can contain valid data before the first daily tick.

Party images and names use `psf_government_leader_group`: an independent government represents itself; a coalition chooses its strongest legal governing party before other organization types, with stable numeric IDs breaking equal influence. The choice is presentation only and does not change coalition membership or the weighted governing program. Name/image getters also require legal status and active governing membership. Caretaker or unknown identities use the native unknown image instead of showing a stale party or ideology.

Selecting a foreign organization, opening a chart, changing tabs or closing the sidebar never writes foreign political state. All three political mutation buttons require `tag = ROOT` both in their enable trigger **and inside the effect**, together with a valid current status and sufficient political power. Ban also rejects governing organizations. Costs are 50 PP to ban, 25 PP to legalize, and 25 PP to activate. Low-level framework effects stay separate from those player-facing costs.

When the player changes the viewed country while an organization is selected, `psf_ui_selection_is_current` checks the new profile. An invalid old selection falls back to the organization list instead of showing an empty details pane.

All identity, page, membership and status comparisons emit `check_variable = { var = ... value = ... compare = equals }`. This is essential because the engine's default comparison is greater than or equal and PSF identifiers are stable, nonsequential numbers.

UI selection variables are normal country variables owned by the player, as in established scripted-GUI usage. Players controlling the same country share that country's selections; PSF does not claim local per-client selection isolation for cooperative same-country multiplayer.

## Icons and localization

`psf/icons.py` provides large and small sprites for every organization and ideology archetype. Defaults alias existing base-game ideology, idea and texticon textures; generated mods do not redistribute those DDS files or substitute hand-drawn geometric badges. Category artwork identifies a type of organization and does not claim to reproduce a historical party emblem. Authors can replace the two sizes independently. List backgrounds, headers, buttons, scrollbars and pie overlays also use original game assets.

To supply authored graphics, define `small_icon` and `large_icon` as existing `GFX_...` sprite identifiers and provide their `.gfx`/texture assets in the content mod. Author-supplied small icons should use a 24×24 logical canvas and large icons 64×64. Default small sprites use the game's compact texticon assets; spectrum markers scale those to approximately 16 pixels, while custom 24-pixel sprites use a separate two-thirds scale. Default idea artwork follows the original 60×68 spirit-entry reservation. A 72×76 clipped frame bounds all detail-page large artwork before the adjacent text and status rows. The original texture bytes were not supplied, so these bounds use native GUI declarations rather than measured DDS dimensions.

The UI generates complete English and Simplified Chinese `psf_ui_*` localization with UTF-8 BOM. Static `$psf_...$` references are resolved during compilation to the actual localized labels and descriptions; live `[?variable]` and `[PSFUI...]` expressions remain for the engine to evaluate in the viewed country. This avoids the literal `$psf_group_...$` and `$psf_ui_detail_metrics_...$` strings seen in the supplied tooltip screenshot. Unknown static references and reference cycles fail the build rather than producing raw keys in the game. No external static localization aliases are implicitly accepted by this UI resolver; authors provide bilingual literal text or references to declared PSF labels. Framework content owns the `psf_group_*`, `psf_axis_*`, `psf_ideology_*`, `psf_regime_*` and `psf_alliance_*` keys. Descriptions and tooltips use those keys rather than hardcoded country names. Localization definitions derive organization ideology, legal status, regime, coalition role and membership from current variables.

An organization can be both legally prohibited and operationally underground. The status tooltip distinguishes that combination from ordinary clandestine activity; moving underground does not silently imply legalization.

Displayed organization influence is `psf_g_<id>_effective_influence`. A tooltip exposes baseline `psf_g_<id>_influence` and `psf_g_<id>_modified_influence` before the legal-status restriction. Support, satisfaction and spectrum markers read the corresponding `modified_*` values. Applying or removing a temporary source therefore changes the list, details, charts and axis markers together without overwriting base attributes.

For every applicable named source, scripted localization checks its active flag and remaining-day variable. Active timed sources show their localized name and remaining days; permanent sources show "until removed". Inactive sources produce no line. These details are available from the organization's row and details tooltip, alongside the active source count. Native idea/trait modifiers continue to use the engine's own modifier tooltips, with their numerical contributions included in the displayed effective values.

## Verification

`python -m unittest tests.test_ui -v` covers retained native widget identities/ancestry, unchanged faction/balance-of-power controls, both native pregame party bindings, hard failure on a changed native tree, stable numeric IDs, explicit comparisons, foreign-country action isolation, modified spectrum positions and overlapping-position click access, authored icon overrides, clipped large artwork and marker scales, bilingual key parity, byte-level root encoding, explicit domestic/foreign text and image scopes, direct-control callback ownership, mutually exclusive pages and selected tabs executed through navigation and country changes, resolved static labels, authored-color pixels and swatches, complete inset pies, native row chrome, a 24-row overflowing viewport, and legal-government/unknown-artwork getters.

`python -m unittest discover -s tests -p 'test_charts.py' -v` executes the emitted HOI4 cache effects in the strict script interpreter. It checks support/influence separation, changed modifier and suppression values, stale-array replacement, zero-total safety, fractional allocation, and date-specific country-selection snapshots. Unknown engine commands fail instead of being silently ignored.

`python tools/ui/audit_layout.py <compiled-content-mod> --svg <output.svg> --report <report.json>` checks summary bounds, the restored foreign party slot, native control boundaries, actual token origins, scrollbar backgrounds/gutters and viewports, direct-control callback ownership, complete script/window linkage, page parents and hidden-widget vertical extents. Console output is compact; the optional report contains every per-control check. The optional SVG is an explicitly labelled geometric projection of the emitted coordinates, not a game screenshot. In the supplied native layout, the political summary ends at Y=382 before the native management strip begins at Y=383; the diplomatic summary ends at Y=246 before the focus area at Y=248, both measured from their native window roots.

The real Rust cwtools validator validates generated GUI, scripted GUI, scripted localization and references together with the framework. Its raw report retains missing-DDS diagnostics from the supplied script-only archive; a separate, pinned list classifies only exact paths already declared in original native GFX files as external game dependencies. A complete `--vanilla` installation receives no such classification. Neither case constitutes a rendered game test. A release check in HOI4 should confirm the politics view, a foreign diplomacy view, tooltips, scrollbars, both lobby routes, and organization operations at the user's chosen resolution/UI scale. No screenshot in this repository should be interpreted as a completed engine render unless explicitly identified as one.
