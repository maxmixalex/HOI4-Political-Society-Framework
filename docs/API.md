# Script API

These are real names generated by [`psf/runtime.py`](../psf/runtime.py), with playable wrappers in [`psf/gameplay.py`](../psf/gameplay.py). The compiled `psf-registry.json` lists the exact IDs, variable names and generated effect/trigger names for a manifest. The examples below use IDs present in the supplied vanilla content.

**Scope:** call public political APIs in the country whose PSF profile owns the organization or alliance. Organization-specific operations guard the profile and do not mutate a different country's similarly named political state. The domestic UI adds ownership and political-power checks; low-level script APIs are building blocks for authorized content and do not include player costs.

## Calling convention

All calls use ordinary HOI4 scripted-effect or scripted-trigger syntax:

```text
psf_activate_ger_zentrum = yes
```

Inputs are temporary variables set in the same effect execution before the call:

```text
set_temp_variable = { psf_amount = 5 }
psf_add_ger_spd_support = yes
```

There is no `psf_add_ger_spd_support = { amount = 5 }` parameter-block API. The compiler emits standard named wrappers rather than relying on such syntax.

| Temporary input | Used by |
| --- | --- |
| `psf_amount` | Numeric add/set operations and legitimacy/cohesion changes |
| `psf_position` | A specific axis setter |
| `psf_threshold` | Generated `*_at_least` triggers |
| `psf_group` | Generic organization dispatchers, using a numeric organization ID |

Set an input immediately before the call; nested effects may reuse temporary names. A negative `psf_amount` subtracts from an additive metric. Setters replace the metric. Score operations clamp to 0…100; position setters clamp to −100…100.

## Initialization and refresh

| Effect | Behavior |
| --- | --- |
| `psf_initialize` | Initialize a country once, selecting its authored tag or fallback profile |
| `psf_refresh` | Recompute current profile's effective influence, memberships, government positions, classification, mismatch and UI revision |
| `psf_refresh_modifiers` | Update the legitimacy dynamic-modifier inputs |
| `psf_begin_transaction` | Suppress routine intermediate full refreshes |
| `psf_commit_transaction` | Clear the batch flag and perform a full refresh |
| `psf_hold_election` | Invoke the current profile's election when its institution permits elections |
| `psf_monthly` | Execute a monthly model update; intended for lifecycle integration and controlled tests |
| `psf_daily_modifiers` | Apply exactly one day of organization drift, expire timed sources, refresh and synchronize native support; already called by the supplied country-scoped `on_daily` |

Initialization is idempotent. It does not reapply starting scores to an existing save. Directly calling a specific `psf_init_<profile>` is available in the generated registry but should be reserved for deliberate integrations; it still refuses a country already initialized.

Transactions do not provide rollback, nesting or security. Commit in the same branch. A change of government deliberately refreshes immediately because it changes ownership of derived governing state. Do not use an unfinished transaction to obtain stale permission checks.

```text
GER = {
    psf_begin_transaction = yes
    psf_legalize_ger_spd = yes
    set_temp_variable = { psf_amount = 6 }
    psf_add_ger_spd_influence = yes
    set_temp_variable = { psf_amount = 12 }
    psf_add_ger_spd_satisfaction = yes
    psf_commit_transaction = yes
}
```

## Organization activity and prohibition

For each organization ID `<group>`, the compiler emits:

| Effect pattern | Conditions and result |
| --- | --- |
| `psf_activate_<group>` | Inactive → legal; clears statutory prohibition |
| `psf_legalize_<group>` | Underground/suppressed → legal; clears prohibition and adds eight satisfaction |
| `psf_ban_<group>` | Active non-governing group not currently suppressed → suppression; records prohibition, −15 satisfaction and −3 legitimacy |
| `psf_underground_<group>` | Legal or suppressed → underground activity; retains its statutory prohibition state |
| `psf_deactivate_<group>` | Active non-governing group → inactive |

Activity and statutory prohibition are distinct. A banned group with sufficient support can reorganize underground without the state repealing its ban. Accordingly, `is_banned` and `is_underground` can both be true. The activity value `3` is immediate suppression; `is_suppressed` checks that specific state.

A group cannot be banned or deactivated while it is a current government member. An operation that moves a member underground removes its government membership. Other alliance memberships can remain. Support and baseline influence persist across legal-access transitions.

Examples:

```text
GER = {
    psf_activate_ger_zentrum = yes
    psf_legalize_ger_spd = yes
    psf_ban_ger_spd = yes
}
```

The last two calls are separate state changes; a content author should normally choose one based on the event's outcome. Repeating a transition while already in its destination activity state does not repeat its rewards or costs. A later repression of an underground network is a new transition.

### Scores

Each of these patterns exists for `support`, `influence` and `satisfaction`:

```text
set_temp_variable = { psf_amount = 4 }
psf_add_ger_spd_support = yes

set_temp_variable = { psf_amount = 25 }
psf_set_ger_spd_influence = yes

set_temp_variable = { psf_amount = -10 }
psf_add_ger_spd_satisfaction = yes
```

Influence setters affect baseline institutional resources. The runtime derives effective influence from activity status. Writing an effective-influence variable directly is temporary and will be overwritten at refresh.

### Native and named organization modifiers

Every group/attribute pair has native `add`, `factor` and `daily` modifier keys. For the vanilla SPD example, these can be placed inside a normal idea or dynamic modifier:

```text
modifier = {
    psf_ger_spd_support_add = 5
    psf_ger_spd_influence_factor = 0.10
    psf_ger_spd_satisfaction_daily = 0.05
    psf_ger_spd_position_economy_add = -8
}
```

These are generated `common/modifier_definitions` entries consumed through the engine's `modifier@` accessor. No new engine-built-in political stat is assumed. The owning country is the recipient of the idea or trait. Native modifier changes are observed at the next refresh, at most the next daily pulse; an integration can call `psf_refresh = yes` explicitly for an immediate update.

Named sources declared by the content manifest can be applied or removed with one call:

```text
ENG = {
    psf_add_eng_tuc_modifier_labor_compact = yes
}

# Later, in the same country's scope:
psf_remove_eng_tuc_modifier_labor_compact = yes
```

The vanilla source lasts 90 daily pulses, adds 12 effective satisfaction, and accumulates 0.02 base influence per active day. Its satisfaction bonus disappears when removed or expired; accumulated influence remains. Reapplying the same source refreshes its duration, while distinct sources stack. See [MODIFIERS](MODIFIERS.md) for the exact formula, timed overrides, triggers, registry and native examples.

### Spectrum position

One setter exists for every group/axis combination:

```text
set_temp_variable = { psf_position = -35 }
psf_set_ger_spd_position_economy = yes
```

The setter reclassifies that group and refreshes derived state. It does not automatically change the regime. If your integration also requires an immediate native government-ideology projection after changing the governing program, call `psf_export_government` after the finished update.

### Generic dispatch

The named wrappers avoid numeric lookups for most content. Generic code can instead use the stable numeric ID recorded by `inspect` or `psf-registry.json`:

```text
# 575174 is ger_spd in the supplied manifest.
set_temp_variable = { psf_group = 575174 }
set_temp_variable = { psf_amount = 3 }
psf_add_support_group = yes
```

Generic dispatchers are `psf_activate_group`, `psf_legalize_group`, `psf_ban_group`, `psf_underground_group`, `psf_deactivate_group`, `psf_add_support_group`, `psf_add_influence_group` and `psf_add_satisfaction_group`. Unknown or foreign-profile IDs do not match a dispatch branch. Obtain IDs from the actual compiled manifest if an author has supplied `numeric_id` overrides.

## Alliances and government

The order of IDs in membership calls is **alliance first, group second**:

```text
FRA = {
    psf_join_fra_popular_front_fra_radical = yes
    psf_join_fra_popular_front_fra_sfio = yes
    psf_govern_fra_popular_front = yes
}
```

| Effect pattern | Behavior |
| --- | --- |
| `psf_join_<alliance>_<group>` | Add an active group; joining the current governing alliance requires legal status |
| `psf_leave_<alliance>_<group>` | Remove this membership only |
| `psf_govern_group_<group>` | Appoint a legal organization directly; preserve all alliance memberships |
| `psf_clear_government` | Clear the current government without dissolving independent alliances |
| `psf_govern_<alliance>` | Form a government with at least one legal member possessing influence; previous government role becomes opposition |
| `psf_dissolve_<alliance>` | Deactivate the agreement and clear its membership; a governing dissolution costs eight legitimacy |
| `psf_add_<alliance>_cohesion` | Add `psf_amount`, clamped 0…100 |

Joining an inactive alliance reactivates it and restores its declared initial cohesion. A group can participate in more than one agreement. Governing membership is derived from either the selected independent group or the selected alliance. `psf_governing_group` and `psf_governing_alliance` are mutually exclusive; neither is required during a caretaker period. A party's name and compatibility ideology do not select it automatically.

Taking office raises newly governing legal members' satisfaction; leaving office through a government replacement reduces departing members' satisfaction. An explicit government formation projects the resulting government classification to the native compatibility state when the bridge permits it.

`psf_government_leader_group` is the derived display representative. For an
alliance it prefers legal governing electoral organizations or parties, then
selects the strongest effective influence; stable numeric IDs break ties.
Only a government with no such party falls back to another organization.
It is zero for a caretaker. This does not change coalition identity or appoint
an engine character. The main political, diplomatic and country-selection
displays use the same rule.

```text
FRA = {
    psf_leave_fra_popular_front_fra_pcf = yes
    set_temp_variable = { psf_amount = -10 }
    psf_add_fra_popular_front_cohesion = yes
}
```

There is no automatic cost of 100 political power inside `psf_govern_*`; that cost belongs to the player decision. An authored event can call the effect with its own appropriate costs and conditions.

## Institutions and legitimacy

```text
SOV = {
    psf_set_regime_workers_monarchy = yes
    set_temp_variable = { psf_amount = -8 }
    psf_add_legitimacy = yes
}
```

This is an intentional alternate-history institutional change. It leaves the organizations' economic and other positions intact. It also illustrates that the low-level regime setter does not automatically charge the player-facing constitutional-reform cost.

| Effect | Behavior |
| --- | --- |
| `psf_set_regime_<regime>` | Select a declared actual regime, then recalculate mismatch and election permission |
| `psf_add_legitimacy` | Add `psf_amount`, clamp 0…100 and update modifier inputs |
| `psf_rebuild_public_confidence` | Add six legitimacy; player decisions/AI provide their own political-power cost |

Regime identifiers in the supplied example include `parliamentary_republic`, `presidential_republic`, `constitutional_monarchy`, `authoritarian_republic`, `one_party_republic`, `soviet_republic`, `corporatist_monarchy`, `imperial_constitution` and `workers_monarchy`.

## Triggers

Core triggers:

| Trigger | Condition |
| --- | --- |
| `psf_is_initialized` | Country has the PSF initialization flag |
| `psf_has_legitimacy_crisis` | Legitimacy below 30 |
| `psf_has_stable_government` | Effective non-caretaker government and legitimacy at least 60 |
| `psf_has_elections` | Actual regime permits framework elections |
| `psf_is_caretaker` | No effective governing agreement |
| `psf_legitimacy_at_least` | Legitimacy at least temporary `psf_threshold` |
| `psf_has_profile_<profile>` | Country owns that profile |

Organization trigger patterns:

- `psf_<group>_is_inactive`
- `psf_<group>_is_legal`
- `psf_<group>_is_underground`
- `psf_<group>_is_banned` — statutory prohibition, including a reorganized underground group
- `psf_<group>_is_suppressed` — activity state 3 specifically
- `psf_<group>_is_governing`
- `psf_<group>_can_be_banned`
- `psf_<group>_support_at_least`
- `psf_<group>_influence_at_least`
- `psf_<group>_satisfaction_at_least`

Alliance trigger patterns are `psf_<alliance>_is_active`, `psf_<alliance>_is_government` and `psf_<group>_is_in_<alliance>`.

```text
GER = {
    set_temp_variable = { psf_threshold = 20 }
    if = {
        limit = {
            psf_ger_spd_support_at_least = yes
            psf_ger_spd_is_banned = yes
        }
        psf_legalize_ger_spd = yes
    }
}
```

A pure trigger context cannot assign temporary values. Where an effect cannot prepare `psf_threshold`, use an explicit variable check instead:

```text
available = {
    psf_has_profile_ger = yes
    check_variable = {
        var = psf_g_ger_spd_support
        value = 20
        compare = greater_than_or_equals
    }
}
```

Always specify `compare = equals` for identity/state equality. The engine's shorthand default is not a safe exact comparison for hashed IDs.

## Readable state variables

Prefer mutation effects to direct writes. The following variables are intended for UI, custom tooltips, conditions and controlled migrations:

| Variable pattern | Meaning |
| --- | --- |
| `psf_g_<group>_support` | Independent support |
| `psf_g_<group>_influence` | Baseline influence |
| `psf_g_<group>_effective_influence` | Influence after legal-access multiplier |
| `psf_g_<group>_satisfaction` | Satisfaction with the government |
| `psf_g_<group>_status` | Activity state 0…3 |
| `psf_g_<group>_prohibited` | Statutory prohibition bit |
| `psf_g_<group>_position_<axis>` | Current coordinate |
| `psf_g_<group>_ideology` | Numeric ID of current closest prototype |
| `psf_g_<group>_governing` | Derived government membership bit |
| `psf_g_<group>_vote_share` | Last framework election's normalized vote share |
| `psf_a_<alliance>_active` | Agreement active bit |
| `psf_a_<alliance>_role` | Government 1, opposition 2, electoral role 3 |
| `psf_a_<alliance>_electoral` | Independent eligibility as an electoral pact |
| `psf_a_<alliance>_g_<group>` | Membership bit |
| `psf_a_<alliance>_cohesion` | Current cohesion |
| `psf_governing_alliance` | Numeric governing agreement ID |
| `psf_government_ideology` | Derived government prototype ID |
| `psf_gov_<axis>` | Effective-influence-weighted government coordinate |
| `psf_regime` | Actual institutional regime ID |
| `psf_alignment_gap` | Institutional mismatch 0…100 |
| `psf_legitimacy` | Current legitimacy 0…100 |
| `psf_legitimacy_change` | Most recently calculated monthly change |
| `psf_election_clock` | Elapsed framework electoral months |
| `psf_election_term` | Profile's current electoral term |
| `psf_election_count` | Completed framework elections |
| `psf_caretaker` | Derived caretaker bit |

Other scratch, bridge snapshot and UI variables are implementation details. A foreign diplomacy view reads the target country's values but stores UI selection on the viewing country. Do not use UI selection as political ownership or as a security predicate for arbitrary external scripts.

## Localization API

Generated static keys include:

| Pattern | Example |
| --- | --- |
| `psf_group_<id>_name` | `psf_group_ger_spd_name` |
| `psf_group_<id>_short_name` | `psf_group_ger_spd_short_name` |
| `psf_group_<id>_desc` | `psf_group_ger_spd_desc` |
| `psf_axis_<id>_name`, `_left`, `_right`, `_desc` | `psf_axis_economy_left` |
| `psf_ideology_<id>_name`, `_desc` | `psf_ideology_social_democratic_name` |
| `psf_regime_<id>_name`, `_desc` | `psf_regime_workers_monarchy_name` |
| `psf_alliance_<id>_name`, `_desc` | `psf_alliance_fra_popular_front_name` |

In a country-scoped localization string:

```text
l_english:
 my_story_society_report:0 "$psf_group_ger_spd_name$: support [?psf_g_ger_spd_support|1], effective influence [?psf_g_ger_spd_effective_influence|1]."
```

Defined text `[PSFUIRegime]` resolves the current actual regime and `[PSFUIGovernment]` resolves the governing agreement in the viewed country context. `[PSFRuntimeGetWinner]` reports the largest individual electoral party from the most recent framework election. The UI generates further group-specific live labels; inspect the emitted scripted-localization files for those internal presentation helpers.

## Native compatibility bridge

| Effect | Purpose |
| --- | --- |
| `psf_export_popularity` | Project active electoral organizations onto native percentages |
| `psf_import_popularity` | Import native percentage deltas where enabled |
| `psf_export_government` | Project the derived government prototype's native category |
| `psf_import_government` | Select a corresponding declared organization after a native government change |
| `psf_capture_engine_government` | Snapshot current native ruling category for integration bookkeeping |

Use organization/alliance effects when your story identifies a particular organization. A native ideology change carries less information and cannot express which of several similarly classified parties should gain support or govern. See [ARCHITECTURE.md](ARCHITECTURE.md) for bridge modes and their limits.

A companion mod may call the named APIs from events, focuses, decisions or on-actions. It should not redefine the generated `psf_*` dispatchers. Keep political story conditions in that mod and let PSF maintain the declared political state.

## Country appearance

`psf_apply_identity`, `psf_set_identity_<id>`, `psf_suspend_identity`, `psf_resume_identity` and `psf_release_identity` manage an opt-in country cosmetic identity in country scope. Full ownership and flag rules are documented in [IDENTITY](IDENTITY.md).
